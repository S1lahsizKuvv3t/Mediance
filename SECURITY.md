# Security policy

## Supported versions

Security fixes are provided for the newest public beta or stable release. Older portable builds may be asked to update before a report is investigated.

## Reporting a vulnerability

Please do not open a public issue for a vulnerability that could expose user data, execute code, alter audio routing outside the selected application, or make unsafe use of a native Windows interface.

Use GitHub's **Report a vulnerability** option in the repository Security tab. Include the affected version, Windows version, reproduction steps, expected impact, and any proof-of-concept material needed to confirm the report.

Do not include account credentials, full lyrics, listening history, or unrelated personal files. A report will be acknowledged after it is reviewed, and publication should wait until a fix or mitigation is available.

Regular crashes and functional bugs that do not have a security impact can use the normal bug-report template.
